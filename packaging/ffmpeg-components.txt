# FFmpeg components of the bundled packages (AppImage, Windows program folder, Docker image): what schneidi uses.
# Read by packaging/linux/build-ffmpeg-lgpl.sh (Linux and MSYS2): FFmpeg is configured with --disable-everything and
# one --enable-<type>=<name> per line. Names as `./configure --list-<type>s` prints them; shell patterns (pcm_*) work.
# A name configure does not know stops the build. Components whose library is missing on a platform (VAAPI on
# Windows, D3D11VA on Linux, an encoder library) are left out by configure itself.
#
# Rules when changing it:
# - Import: keep every decoder/demuxer a camera, phone, screen or game recorder, image or audio tool can write.
#   Users notice a file that does not open, not a few hundred KB. tools/ffmpeg-import-check.sh compares against the
#   full build.
# - Export: every encoder/muxer of core/RenderJob.cpp (render formats), engine/HardwareEncoders.cpp (hardware and
#   GPL-free replacements, proxy encoder), engine/RenderCache.cpp, engine/Transcriber.cpp, engine/Exporter.cpp (GIF).
# - Devices: none, except the lavfi input of the hardware encoder test.
# - Filters: only the bundled ffmpeg program uses them (proxies, render cache, GIF palette, hardware encoder test,
#   SCHNEIDI_ANALYSIS=ffmpeg comparisons) plus those its command line inserts by itself (autorotate, format/rate
#   conversion, -ss/-t). The program itself does not link libavfilter.
